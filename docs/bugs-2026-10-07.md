# Ariadne bug log — 7 October 2026

## Home does not recover some startup requests after a core restart

- **Status:** Deferred for investigation; minor. No fix requested. Continue observing the system during this week's testing.
- **Observed:** After restarting the core, Discover eventually populated, but recent chats remained at “Reading recent chats…” and weather/markets did not populate.
- **Evidence:** The affected Opera tab displayed “Session unavailable: HTTP 502”. Markets displayed an invalid-JSON error containing an HTML doctype. The tab opened at approximately 10:00:51 Thailand time; startup telemetry recorded the restarted core ready at 10:00:55.
- **Confirmed recovery gap:** Recent chats load after successful session startup; failed initial session startup does not automatically retry. Information refresh runs every 15 minutes, while Discover refresh runs every 15 seconds. The GET helper parses JSON before checking HTTP status.
- **Verification:** Subsequent endpoint checks returned 33 recent chats, five market cards and 100 Discover cards. A fresh Home page populated chats and markets. Weather on the fresh test page requested browser location permission; weather data recovery was not verified.
- **Assessment:** Timing is consistent with requests reaching the proxy before the restarted core was ready. The precise cause of the initial gateway failure was not independently established.
- **Possible later investigation:** Startup retry behaviour, independence of chat-history loading, and handling HTML gateway errors. Keep any eventual change narrow.
- **Action taken:** Documentation only. No implementation change, service restart or deployment.

## Adding an interest can report failure after the record was saved

- **Status:** Investigated; deferred during the observation period.
- **Observed:** Adding Thailand with a natural-language description displayed “Interest could not be saved: Signal Service unavailable: timed out” in Configuration. Screenshot supplied by the user: `D:/Downloads/Screenshot 2026-10-07 100907.png`.
- **Verified persisted state:** A read-only GET of the running Signal service `/v1/interests` returned Thailand, enabled, priority 1, with the complete submitted description. Its creation/update timestamp was 7 October 2026 at 10:07:54 Thailand time. No duplicate submission was made during diagnosis.
- **Confirmed code path:** Signal service `upsert_interest` persists the record before synchronous semantic enrichment and cached briefing rebuild, then returns the response. The core's Signal client uses a five-second timeout. Semantic enrichment can wait for its lock and embedding requests allow up to 90 seconds. Configuration treats the timed-out response as a failed save without reconciling persisted state.
- **Assessment:** This path permits a successful write followed by a client timeout and misleading failure message. Exact duration and internal phase of this particular timed-out POST were not independently captured.
- **Possible later investigation:** Separate save acknowledgement from expensive semantic refresh using the existing refresh mechanism, and reconcile ambiguous timeout responses with persisted state. Avoid duplicate writes or merely increasing every request timeout.
- **Action taken:** Read-only diagnosis and documentation. No code changes, service restart, deployment or interest mutation.

## Interest priority slider resets after a timed-out save

- **Status:** Fixed in Configuration UI on 7 October 2026; included in the accepted maintenance checkpoint.
- **Cause:** The slider automatically posted on change and restored its previous value on any failed response, including timeouts after a committed write. There is no periodic adaptive-management refresh loop on this page. A read-only check confirmed Thailand had already reached priority 5.
- **Change:** A changed slider now exposes Save and Unsaved. Draft priorities survive management rerenders. Save uses the existing endpoint and preserves metadata. Failed responses trigger an authoritative registry read; matching stored priority confirms success, otherwise the draft remains available to retry. Duplicate pending submissions are suppressed.
- **Validation:** Four slider regression tests, two existing Configuration state tests and six Configuration page tests passed. Three broader cleanup persistence tests failed due to missing `music` in their fixtures; these failures were reproduced with unchanged HEAD tests and unchanged cleanup implementation. An isolated browser preview proved Save visibility, recovery from a committed write with a simulated timeout, and priority 5 after reload. The live page serves the new Save control and displays real Thailand priority 5. Production interest data was not modified by these tests.
- **Scope:** Configuration UI and focused tests only. Original endpoint timing and Home restart recovery issues remain deferred. No service restart or ranking change.
