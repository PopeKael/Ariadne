# n8n News Service workflow exports

These sanitized definitions are saved from the published Synology workflows with n8n's built-in **Export JSON** action. Workflow IDs, nodes, parameters, connections, settings and activation state match the running definitions. Credential IDs and pinned execution data are removed; credential names remain as mapping hints. Credential values and tokens stay only in n8n.

- `news-service-collector.json` — `VP0Bro3F98I523YD`, **News Service - manual collector (draft)**. Published and active. Its hourly schedule collects enabled YouTube sources; maintains the last-known registry mirror; keeps two newest cards per source in **News Service Publications**; stores collected IDs and delivery attempts in **News Service Delivery Ledger**; syncs the card window and prior delivery receipts to Ariadne; and sends eligible new Discord cards through the existing **Ariadne Integration** credential.
- `news-service-publication-snapshot.json` — `HGKHZh3Uuw88fJrl`, **News Service - LAN snapshot (draft)**. Published and active. It reads **News Service Publications**, sorts by YouTube `published_at` descending with stable source/video tie-breakers, and returns the newest two per source.

The word “draft” is part of both existing workflow names. The published collector uses the current Ariadne registry when available and the last-known registry row when Ariadne is offline. Disabled channels and channels without a configured Discord destination are not collected for posting. The persisted Stage 4 activation timestamp excludes earlier publications. A video already sent remains suppressed even if its destination is changed. Each HTTP attempt is recorded separately; HTTP 429 responses are retried on later hourly cycles up to three attempts. Network errors and ambiguous server responses are marked uncertain and are not automatically repeated, avoiding duplicate posts. Rejected and unresolved attempts remain in the ledger and prevent their publication rows from being pruned.

Manual **Post to Discord** controls in Ariadne remain available for testing and recovery. The Ariadne automatic sender remains disabled; Synology is the sole automatic sender. Receipts are copied back during a subsequent successful synchronization, so the cache and persistent receipt history remain available while Ariadne is offline.

`test_news_n8n_stage4_workflow.py` executes the exported Code-node logic with synthetic inputs to check activation gating, disabled sources, duplicate suppression, two-item retention, Shorts inclusion and sort order. Run it with the focused Ariadne News Service tests.
