## Discord delivery path

`Prepare Discord Candidates` retains the established activation boundary, source rules, delivery-key deduplication and Components V2 formatter. `Production Delivery Guard` and `Mark Delivery Inflight` precede `Code in JavaScript4`, which parses the persisted `state_json` and exposes its validated `destination`. The three-rule `Switch` then routes on `$json.destination`: `ai_noise`, `thailand_news`, or `news_3cf8b10043ab9e794da82060`. Each branch uses the matching encrypted `discordWebhookApi` credential through `Ariadne Discord Webhook`. All three sender outputs pass through `Build Delivery Receipt` and `Persist Delivery Receipt`. The bot-based `Post Discord Card` node is removed from the active workflow. Manual Ariadne publishing controls and unrelated Discord bot workflows are unchanged.

The sender returns Discord's message ID and safe response metadata to the existing ledger. The route extracts the validated destination from the persisted receipt, then sends through the destination's existing encrypted webhook credential. The Switch node was upgraded through the n8n editor to type version 3.4, and its three rules now evaluate the destination expression without a literal equals sign. All successful sender outputs still pass through the existing receipt ledger. Sent, inflight, uncertain, rejected and pending deliveries remain suppressed; rate-limited and known pre-send failures follow the existing bounded retry rules. Historical rows and the activation timestamp are preserved. Only production-mode executions send or synchronize live; editor/manual runs remain dry runs.
