# Ariadne handover — 2026-08-15

This is the short orientation document for anyone picking up Ariadne after the
repository consolidation. It records durable project decisions and the useful
lessons from the earlier exploratory work. It is not intended to reproduce
every Codex conversation.

## Where the project is now

`D:\Downloads\Ariadne` is the canonical local repository and the working
project boundary. The GitHub repository is:

`https://github.com/PopeKael/Ariadne`

The four parcels are now represented in one project:

1. **Knowledge Vault — memory**: the user-owned knowledge and identity data.
2. **MCP — nervous system**: the stdio and local HTTP access boundaries.
3. **Toolshed — hands**: controlled local workflows and service actions.
4. **Workspace/interface — environment**: the browser dashboard, tray process,
   launcher, sessions, and operational controls.

The local control plane is currently served at:

`http://localhost:8765/`

The service remains loopback-only on `127.0.0.1`; `localhost` is the friendly
user-facing name. The desktop shortcut and scheduled task now launch the
canonical repository.

## What has been consolidated

## Useful rabbit holes and their outcomes

### Separate project locations

The early work was split between `D:\Downloads\KnowledgeVault` and
`D:\Documents\Codex\Ariadne`. That was useful for experimentation but made
the project boundary ambiguous. Ariadne is now the canonical integration
location. The two source trees are retained as rollback references until the
new location has been exercised normally.

### Duplicate control panels and ports

The older Knowledge Vault shortcut used a separate control panel and port.
The canonical launcher now starts the integrated control plane on port `8765`.
The old shortcut was preserved with an explicit old-location name rather than
silently overwriting it.

### Downloads as a working root

The Downloads folder is a practical local staging root, not Ariadne's internal
architecture. Scratch folders such as images, videos, documents, and temporary
working material may remain alongside the project. The Ariadne repository owns
the system code and the Vault content it directly manages; unrelated scratch
folders do not need to be moved into the repository.

### GitHub naming

The repository is named **Ariadne** because the Knowledge Vault is one parcel
of Ariadne, not a competing top-level project. A separate KnowledgeVault
repository is not required for the consolidated architecture.

### Generated catalogue state

`00_System/library.json` contains generated, machine-specific catalogue data.
The newer working-tree version from the old Vault location was not copied
blindly. It needs a deliberate privacy/path audit before any refresh is
committed. Private Vault content and runtime/generated state remain excluded
by `.gitignore`.

## How to carry conversation history forward

Codex conversations remain useful working material, but they should not be
bulk-copied into the source repository. When a conversation produces a durable
decision, test result, architectural constraint, or rejected approach, record
that result in `docs/`, the relevant component README, or the Knowledge Vault
according to whether it describes Ariadne or Wazza's managed knowledge.

This keeps the repository readable while preserving the important reasoning.
The current checkpoint, four-parcel definition, merge architecture, and this
handover are the starting references for the next session.
